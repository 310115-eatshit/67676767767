# 開發經驗

## 2026-11-26：用純前端做第一個可玩的街區原型

### 做法

- 以單一 HTML 頁面和 Canvas 2D 畫出俯視角街區，不依賴外部圖片、遊戲引擎或套件。
- 讓玩家用方向鍵／WASD 移動，並提供觸控方向按鈕，讓桌面與手機都能操作。
- 允許點擊／輕觸地圖設定步行目標，降低手機操作門檻；保留方向鍵與觸控按鈕作為替代方式。
- 將少量興趣地點放在資料陣列中；玩家走近後可互動，先以短描述呈現城市氣氛。
- 把原型直接放在專案介紹頁，方便每次 Pages 部署後立即試玩。

### 適用範圍

適合快速驗證 2D 地圖尺度、移動速度、觸控操作與地點互動概念，也適合內容量小、無外部素材、要直接部署到 GitHub Pages 的展示原型。當地圖、碰撞、角色或動畫增多時，應再拆分資料與繪圖程式，並評估使用專門的遊戲引擎或模組架構。

### 注意事項

- Canvas 對輔助科技不如原生 HTML 元素容易理解；重要資訊要同時用頁面文字呈現，並保留清楚的鍵盤操作說明。
- 觸控按鈕使用 pointer 事件時，需在放開、取消或移出按鈕時清掉輸入狀態，避免角色持續移動。
- GitHub Pages 工作流程最好先把要發布的檔案複製到獨立目錄，再上傳該目錄，避免把 `.git` 等建置環境內容一起發布。
- 讓 Canvas 可用 Tab／點擊取得鍵盤焦點，否則頁面級方向鍵監聽不一定收到輸入；初始位置放在一個可互動地點附近，能讓玩家一進來就理解探索循環。
- 以圓形玩家半徑和矩形建築邊界做簡單碰撞，X/Y 軸分開移動可保留沿牆滑行的手感；適合小地圖原型，複雜地形再改成碰撞圖層。水面邊界也要把玩家半徑算進去，讓角色停在岸上。
- 點擊移動可直接沿直線接近目標並用軸向碰撞滑行，適合街區中短距離移動；目標被建築完全擋住時需要之後加入尋路或明確的阻擋提示。
- 玩家出生點、居民和目標物件都要避開建築碰撞矩形；本次測試發現出生點和居民落在建築區，導致玩家無法走動，移開建築後才可完成支線。

### 本次驗證

在本機預覽中確認頁面和地圖繪製可運作，並實際走完小安支線（對話、點擊移動尋物、返回居民、交還選擇與信任回饋）。用 Node.js `--check` 檢查內嵌 JavaScript 語法，瀏覽器沒有 JavaScript 執行錯誤。GitHub Actions 確實執行，但因儲存庫尚未啟用 Pages 而在 `configure-pages` 步驟失敗；首次部署前需到 Settings → Pages 選擇 GitHub Actions。這不是原型程式錯誤。

## 2026-11-26：用一條短支線驗證探索、交談與選擇

### 做法

- 把玩家出生點放在公園居民附近，讓初次互動很容易發現。
- 用明顯但簡單的地圖符號提示可交談角色和可尋找物品。
- 把支線拆成「詢問 → 找到物品 → 回來選擇處理方式」三個狀態，避免一次塞入太多系統。
- 用不同文字回饋兩種選擇，並只在其中一種選擇時調整居民信任，為後續角色關係留下可擴充的欄位。

### 適用範圍

適合在開放世界原型早期驗證角色互動、探索目標與簡單選擇後果。事件數量增加時，應將任務狀態與對話內容抽成資料，避免把每條支線都寫進輸入處理函式。

選擇後果可以先表現在後續對話，再逐步擴展到事件解鎖或角色關係。若需要重新整理後仍保留關係值，應另行加入存檔設計；目前原型狀態只存在當次頁面工作階段。

### 本次驗證

本機瀏覽器完整驗證了對話、點擊移動、尋回素描本、返回角色、顯示兩種選項、兩個收尾分支，以及各自不同的後續對話。交還給小安會增加信任並解鎖河岸散步線索；交到服務台則回覆她已領回素描本。也檢查角色走向建築與水面的路線，角色會停在建築外緣及岸邊。Node.js 語法檢查通過，瀏覽器沒有回報 JavaScript 執行錯誤。

## 2026-11-26：用同一組地點資料加入可選拍照收集

把可探索地點保存在一個資料陣列中，新增拍照完成狀態，首次互動才增加收集數並改變地圖標記。這讓自由散步除了角色支線，還有一個不需接任務也能完成的小目標。

適合用於地點數量少、想快速加入收藏或探索進度的靜態原型。拍照與任務資料增加後，應把可互動物件和狀態抽成一致的資料模型；目前計數仍只存在當次頁面工作階段。

本機已驗證第一次拍照會將計數從 0/5 更新到 1/5，再拍同一地點不會重複增加；河岸碼頭的移動與拍照互動也能完成。

## 2026-11-26：GitHub Pages 靜態部署

### 做法

使用官方 Pages Actions（`configure-pages`、`upload-pages-artifact`、`deploy-pages`），限定部署權限為 `contents: read`、`pages: write`、`id-token: write`，並讓 `main` 分支推送與手動觸發都能部署。

### 適用範圍

適用於沒有伺服器需求的純 HTML、CSS、JavaScript 專案。若遊戲後續需要帳號、多人連線或保存雲端進度，Pages 仍可發布前端，但後端服務需另外規劃。
